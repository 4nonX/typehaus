# The typehaus API

typehaus has a stable HTTP/JSON API for connecting other tools: ticket systems, document servers, brand portals, accounting, scripts.

- **Base URL:** `https://<your typehaus>/api/v1`
- **Description:** `GET /api/v1/openapi.json` (OpenAPI 3.1, generated by the server itself – always matches the version you run). Load it into Swagger UI, Postman, Insomnia or a code generator.
- **Stability:** everything under `/api/v1` changes only compatibly for as long as typehaus is on version 1: new endpoints and new fields may appear, existing ones keep their meaning. Ignore fields you don't know. Endpoints outside `/api/v1` belong to the web UI and the apps and may change at any time.

## Tokens

An administrator creates tokens in the web UI under **API → New token**. Create one per tool, so you can revoke them separately.

| Access | Can |
|---|---|
| **Read** | `GET` everything: fonts, collections, licenses and their documents, requests, people, computers, reports, the activity log |
| **Read & write** | also change data – everything an administrator can, except managing tokens |

Send the token with every request:

```sh
curl -H "Authorization: Bearer thk_…" https://fonts.example.com/api/v1/licenses
```

- The token is shown **once** when it is created; typehaus keeps only a hash. Store it like a password.
- A token acts for the organisation, not for a person. Changes appear in the activity log as `token:<name>`.
- A token stops working when it is revoked, when it expires, or when the administrator who created it is disabled or loses admin rights.
- Tokens only work on `/api/v1`. They can't sign in, change accounts, act as a computer, or manage tokens.
- **Font downloads follow the license rules without exception.** Fonts whose license doesn't allow direct downloads, or that is enforced and limited to seat holders, or has expired, are left out (named in the `X-Typehaus-Skipped` response header). `TYPEHAUS_DOWNLOADS=false` switches downloads off for tokens too.

## Requests and responses

- JSON in, JSON out (`Content-Type: application/json`). Uploads use `multipart/form-data`.
- Times are Unix seconds; dates (`purchased_on`, `expires_on`) are `YYYY-MM-DD`.
- `PATCH` changes only the fields you send.
- Errors: an HTTP status with `{"error": "…"}` – `400` invalid input, `401` missing, wrong, revoked or expired token, `403` not allowed (e.g. a read token writing), `404` not found, `409` refused because of a conflict (e.g. an enforced license would run out of seats).

## Endpoints

| Area | Endpoints |
|---|---|
| Fonts | `GET /fonts` (`?q=`, `?collection=`), `GET /fonts/{id}`, `GET /fonts/download?ids=1,2`, `POST /fonts` (upload), `PATCH /fonts` (assign a license), `DELETE /fonts` |
| Collections | `GET/POST /collections`, `PATCH/DELETE /collections/{id}`, `POST/DELETE /collections/{id}/fonts` |
| Licenses | `GET/POST /licenses`, `GET/PATCH/DELETE /licenses/{id}`, `GET /licenses/{id}/history`, `GET /licenses/export.csv`, `GET /licenses/history.csv` |
| License documents | `POST /licenses/{id}/documents`, `GET/PATCH/PUT/DELETE /licenses/{id}/documents/{doc}` |
| Font requests | `GET /requests`, `PATCH /requests/{id}` (answer) |
| People | `GET/POST /users`, `PATCH/DELETE /users/{id}`, `GET/POST /groups`, `PATCH/DELETE /groups/{id}` |
| Computers | `GET /devices?all=1`, `DELETE /devices/{id}` (disconnect) |
| Compliance | `GET /inventory`, `GET /inventory.csv`, `GET /reports/usage`, `GET /audit` |

Every endpoint with its fields is in `openapi.json`.

## Examples

```sh
TH=https://fonts.example.com/api/v1
AUTH="Authorization: Bearer $TYPEHAUS_TOKEN"
```

**Licenses that expire within 60 days** (e.g. for a renewal reminder):

```sh
curl -s -H "$AUTH" $TH/licenses | jq '.[] | select(.expires_in_days != null and .expires_in_days <= 60) | {name, expires_on, reference}'
```

**Open font requests** into your ticket system, and answering one:

```sh
curl -s -H "$AUTH" $TH/requests | jq '.[] | select(.status == "open") | {id, user, font, purpose}'
curl -s -X PATCH -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"status": "done", "answer": "Added to the Brand collection."}' $TH/requests/42
```

**Upload fonts into a collection** and give them a license:

```sh
curl -s -H "$AUTH" -F collection_id=3 -F files=@BrandSans-Regular.otf -F files=@BrandSans-Bold.otf $TH/fonts
# → {"results": [...], "font_ids": [17, 18]}
curl -s -X PATCH -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"font_ids": [17, 18], "license_id": 5}' $TH/fonts
```

**Install a collection automatically** for everyone it applies to:

```sh
curl -s -X PATCH -H "$AUTH" -H "Content-Type: application/json" -d '{"mode": "installed"}' $TH/collections/3
```

**Attach an invoice** to a license:

```sh
curl -s -H "$AUTH" -F kind=invoice -F shared=0 -F files=@Rechnung-2026-0142.pdf $TH/licenses/5/documents
```

**A document server fetching its fonts** (license rules apply; the response is the font file, or a ZIP for several):

```sh
curl -s -H "$AUTH" -o fonts.zip "$TH/fonts/download?ids=17,18"
```

**Audit export** for a foundry:

```sh
curl -s -H "$AUTH" -o licenses.csv $TH/licenses/export.csv
curl -s -H "$AUTH" -o usage.csv $TH/licenses/history.csv
curl -s -H "$AUTH" -o outside.csv $TH/inventory.csv
```
