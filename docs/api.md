# The typehaus API

typehaus has a stable HTTP/JSON API for connecting other tools: ticket systems, document servers, brand portals, accounting, scripts.

- **Base URL:** `https://<your typehaus>/api/v1`
- **Description:** `GET /api/v1/openapi.json` (OpenAPI 3.1, generated by the server itself – always matches the version you run). Load it into Swagger UI, Postman, Insomnia or a code generator.
- **Stability:** everything under `/api/v1` changes only compatibly for as long as typehaus is on version 1: new endpoints, fields, error codes and webhook events may appear; existing ones keep their name, type and meaning, and nothing that was optional becomes required. Ignore fields you don't know. The 1.0.0 contract is kept in the repository (`internal/server/testdata/openapi-v1.json`) and every build is tested against it. Endpoints outside `/api/v1` belong to the web UI and the apps and may change at any time.

## Tokens

An administrator creates tokens in the web UI under **Integrations → API tokens → New token**. Create one per tool, so you can revoke them separately.

| Access | Can |
|---|---|
| **Read** | `GET` everything: fonts, collections, licenses and their documents, requests, people, computers, reports, the activity log |
| **Read & write** | also change data – everything an administrator can, except managing tokens |

Send the token with every request:

```sh
curl -H "Authorization: Bearer thk_…" https://fonts.example.com/api/v1/licenses
```

- The token is shown **once** when it is created; typehaus keeps only a hash. Store it like a password.
- A token acts for the organisation, not for a person. Changes appear in the activity log as `token:<name>`.
- A token stops working when it is revoked, when it expires, or when the administrator who created it is disabled or loses admin rights.
- Tokens only work on `/api/v1`. They can't sign in, change accounts, act as a computer, or manage tokens.
- **Rotation without downtime:** *New secret* issues a new token value; the old one keeps working for a grace period you choose (up to 7 days). Responses to a superseded token carry `X-Typehaus-Token-Superseded` (until when it still works); tokens with an expiry carry `X-Typehaus-Token-Expires`. Both are RFC 3339 times. Tokens can also be renamed and given a new expiry.
- **Font downloads follow the license rules without exception.** Fonts whose license doesn't allow direct downloads, or that is enforced and limited to seat holders, or has expired, are left out (named in the `X-Typehaus-Skipped` response header). `TYPEHAUS_DOWNLOADS=false` switches downloads off for tokens too.

## Requests and responses

- JSON in, JSON out (`Content-Type: application/json`). Uploads use `multipart/form-data`.
- Times are Unix seconds; dates (`purchased_on`, `expires_on`) are `YYYY-MM-DD`.
- `PATCH` changes only the fields you send.

### Errors

Every error is an HTTP status with a JSON body:

```json
{"error": "an enforced license has no free seats", "code": "seats_exhausted"}
```

`error` is for people and may change; `code` is stable and meant for programs. The codes are listed in `openapi.json` (schema `Error`). New codes may be added – treat an unknown one by its HTTP status.

| Status | Typical codes |
|---|---|
| `400` | `invalid_request` |
| `401` | `unauthorized`, `token_invalid`, `token_expired`, `token_owner_inactive` |
| `403` | `forbidden`, `admin_only`, `read_only_token`, `tokens_not_allowed`, `license_refused`, `downloads_disabled` |
| `404` | `not_found` (also for objects the caller can't see), `feature_disabled` |
| `409` | `conflict`, `already_exists`, `seats_exhausted`, `limit_reached`, `idempotency_in_progress`, `not_configured` (an identification service needs a key) |
| `413` | `payload_too_large` |
| `422` | `idempotency_key_reused` |
| `429` | `rate_limited` |
| `502` | `upstream_error` (a font catalog or identification service failed or couldn't be reached) |

### Lists: paging and filters

List endpoints return a JSON array, one page at a time: `?limit=` (default 100, at most 1000) and `?offset=`. `X-Total-Count` holds the number of entries matching the filters across all pages, and a `Link` header points to the `next` and `prev` page. Every simple field of the entries can be used as an exact filter, e.g. `/licenses?enforced=true`, `/requests?status=open,declined` (comma-separated: any of them; text ignores case). `openapi.json` lists the filters per endpoint.

The activity log (`/audit`) is newest first and pages with `?before=<id>` instead; its `Link: rel="next"` header holds the next URL.

### Retries: Idempotency-Key

Send `Idempotency-Key: <your unique value>` (up to 255 characters) with a `POST`, `PATCH`, `PUT` or `DELETE` to make retrying safe. A repeat with the same key and the same request returns the stored response with `Idempotent-Replayed: true` instead of running again; the same key with a different request is refused (`422 idempotency_key_reused`); while the first request is still running, a repeat gets `409 idempotency_in_progress`. Keys are kept for 24 hours, per token.

### Rate limit

Each token may make `TYPEHAUS_API_RATE` requests per minute (default 600, short bursts allowed). Every response carries `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Policy`; over the limit the answer is `429 rate_limited` with `Retry-After` in seconds. Identifications (`POST /identify`) are also limited to 30 an hour per person, because they use paid outside services.

## Endpoints

| Area | Endpoints |
|---|---|
| Fonts | `GET /fonts` (`?q=`, `?collection=`), `GET /fonts/{id}`, `GET /fonts/download?ids=1,2`, `POST /fonts` (upload), `PATCH /fonts` (assign a license), `DELETE /fonts` |
| Collections | `GET/POST /collections`, `PATCH/DELETE /collections/{id}`, `POST/DELETE /collections/{id}/fonts` |
| Licenses | `GET/POST /licenses`, `GET/PATCH/DELETE /licenses/{id}`, `GET /licenses/{id}/history`, `GET /licenses/export.csv`, `GET /licenses/history.csv` |
| License documents | `POST /licenses/{id}/documents`, `GET/PATCH/PUT/DELETE /licenses/{id}/documents/{doc}` |
| Font requests | `GET /requests`, `PATCH /requests/{id}` (answer) |
| People | `GET/POST /users`, `PATCH/DELETE /users/{id}`, `GET/POST /groups`, `PATCH/DELETE /groups/{id}` |
| Computers | `GET /devices?all=1`, `DELETE /devices/{id}` (disconnect) |
| Compliance | `GET /inventory`, `GET /inventory.csv`, `GET /reports/usage`, `GET /audit` |
| Free font catalog | `GET /catalog` (`?q=`, `?category=`, `?source=`), `POST /catalog/import`, `GET /lookup?name=` |
| Identification | `POST /identify` (an image or image URL) |
| Web fonts | `GET/POST /webkits`, `GET/PATCH/DELETE /webkits/{id}` |
| Webhooks | `GET /webhook-events`, `GET/POST /webhooks`, `GET/PATCH/DELETE /webhooks/{id}`, `POST /webhooks/{id}/secret`, `POST /webhooks/{id}/test`, `GET /webhooks/{id}/deliveries`, `POST /webhooks/{id}/deliveries/{delivery}/redeliver` |

Every endpoint with its fields is in `openapi.json`.

## Examples

```sh
TH=https://fonts.example.com/api/v1
AUTH="Authorization: Bearer $TYPEHAUS_TOKEN"
```

**Licenses that expire within 60 days** (e.g. for a renewal reminder):

```sh
curl -s -H "$AUTH" $TH/licenses | jq '.[] | select(.expires_in_days != null and .expires_in_days <= 60) | {name, expires_on, reference}'
```

**Open font requests** into your ticket system, and answering one:

```sh
curl -s -H "$AUTH" $TH/requests | jq '.[] | select(.status == "open") | {id, user, font, purpose}'
curl -s -X PATCH -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"status": "done", "answer": "Added to the Brand collection."}' $TH/requests/42
```

**Upload fonts into a collection** and give them a license:

```sh
curl -s -H "$AUTH" -F collection_id=3 -F files=@BrandSans-Regular.otf -F files=@BrandSans-Bold.otf $TH/fonts
# → {"results": [...], "font_ids": [17, 18]}
curl -s -X PATCH -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"font_ids": [17, 18], "license_id": 5}' $TH/fonts
```

**Install a collection automatically** for everyone it applies to:

```sh
curl -s -X PATCH -H "$AUTH" -H "Content-Type: application/json" -d '{"mode": "installed"}' $TH/collections/3
```

**Attach an invoice** to a license:

```sh
curl -s -H "$AUTH" -F kind=invoice -F shared=0 -F files=@Rechnung-2026-0142.pdf $TH/licenses/5/documents
```

**A document server fetching its fonts** (license rules apply; the response is the font file, or a ZIP for several):

```sh
curl -s -H "$AUTH" -o fonts.zip "$TH/fonts/download?ids=17,18"
```

**Audit export** for a foundry:

```sh
curl -s -H "$AUTH" -o licenses.csv $TH/licenses/export.csv
curl -s -H "$AUTH" -o usage.csv $TH/licenses/history.csv
curl -s -H "$AUTH" -o outside.csv $TH/inventory.csv
```

**Add a free font family** to the library and a collection:

```sh
curl -s -H "$AUTH" "$TH/catalog?q=hanken" | jq '.[] | {id, family, source, importable}'
curl -s -X POST -H "$AUTH" -H "Content-Type: application/json" -H "Idempotency-Key: $(uuidgen)" \
  -d '{"ids": ["google:hanken-grotesk"], "collection_id": 3}' $TH/catalog/import
```

**Which font is this?** (needs at least one identification service with a key):

```sh
curl -s -H "$AUTH" -F image=@screenshot.png $TH/identify | jq '.results[] | {service, matches: [.matches[] | {name, in_library: (.library != null)}]}'
```

## Webhooks

A webhook sends events to your URL as they happen: fonts added or deleted, license changes, a license expiring (30, 14, 7 and 1 days before) or over its seats, web page views over the monthly limit, font requests, copies found outside typehaus, computers, users, tokens about to expire. `GET /webhook-events` lists them all; `openapi.json` describes each payload in its `webhooks` section. Create webhooks under **Integrations → Webhooks** or with `POST /webhooks`, subscribing to event types, families such as `license.*`, or `*`.

Each delivery is a `POST` with a JSON body

```json
{"id": "evt_…", "type": "license.expiring", "created_at": 1763035200, "data": {…}}
```

and the headers `X-Typehaus-Event`, `X-Typehaus-Delivery` (the same on retries – use it to drop duplicates), `X-Typehaus-Timestamp` and `X-Typehaus-Signature: v1=<hex>`. The signature is HMAC-SHA256 over `<timestamp>.<raw body>` with the webhook's secret (shown once, when created or renewed). Check it before trusting the body, and reject timestamps older than five minutes:

```python
import hmac, hashlib, time

def verify(secret: str, headers, body: bytes) -> bool:
    ts = headers["X-Typehaus-Timestamp"]
    want = hmac.new(secret.encode(), ts.encode() + b"." + body, hashlib.sha256).hexdigest()
    got = headers["X-Typehaus-Signature"].removeprefix("v1=")
    return hmac.compare_digest(want, got) and abs(time.time() - int(ts)) < 300
```

Answer with any `2xx` within 10 seconds. Anything else is retried with growing pauses for about 22 hours; the deliveries of the last 30 days are listed with their answers and can be sent again. Addresses of cloud metadata services are refused as targets.

## Web fonts

A **web kit** (**Integrations → Web fonts**, or `/webkits`) serves library fonts to websites. The site links one stylesheet – no token, it is public:

```html
<link rel="stylesheet" href="https://fonts.example.com/webfonts/<kit token>.css">
```

It declares each font with `@font-face` (WOFF2 with a WOFF fallback, `font-display: swap`; variable fonts with their weight range), under the library's family name. Only fonts whose license includes **web** use and hasn't expired are served; the kit lists the others with the reason. Fonts are only delivered to the kit's domains (checked against `Origin` and `Referer`; `*.example.com` includes subdomains). Each stylesheet load from an allowed site counts as a page view; a license can have a monthly page-view limit, and going over it keeps sites working but flags the license and sends `license.webfont_views`.

## The app's plugin API

Plugins on a computer don't talk to the server: they ask the **typehaus app** on the same computer, which answers for the person signed in there, with the library's license rules. This is how the InDesign, Photoshop and Illustrator panels and the Affinity connection work, and other plugins can use it too. It is not part of `/api/v1` and may change between minor versions.

- `http://127.0.0.1:47130` (`TYPEHAUS_PLUGIN_PORT` changes it), loopback only.
- Every request needs `X-Typehaus-Plugin: 1`. Requests with a web `Origin` are refused and no CORS headers are sent, so websites can't use it.

| Endpoint | Body | Answer |
|---|---|---|
| `GET /v1/status` | – | `{"app", "version", "connected", "server", "user"}` |
| `POST /v1/fonts/check` | `{"fonts": [{"postscript_name"} or {"family", "style"}], "app"}` | `{"fonts": [...]}` with `status`: `active`, `available`, `refused`, `unsupported` or `not_available`, plus `reason`, `installed` and `on_system` |
| `POST /v1/fonts/activate` | as check | switches the `available` fonts on, syncs and waits up to 45 s for the files: `{"fonts": [...], "complete"}` |
| `POST /v1/requests` | `{"font", "purpose", "app"}` | the font request is created on the server |

Where a host app allows only https (Photoshop on macOS), a plugin can use files instead: write `{"method", "path", "body"}` to `<config dir>/plugins/requests/<id>.json` and read `{"status", "body"}` from `<config dir>/plugins/answers/<id>.json`. `<id>` is 8–64 letters, digits, `-` or `_`; `<config dir>` is `~/Library/Application Support/typehaus` on macOS and `%APPDATA%\typehaus` on Windows.
